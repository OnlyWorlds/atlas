## S. State, routing and rooms

1. **State is truth.** UI reads `getState()`, writes through `patchSlice()`, and the router mediates URL and state. Every subscriber fires on every change (no selectors). (`src/core/state.ts`; its header comment still mentions a `select()` that does not exist.)
2. **Force a re-render with a new reference.** Patch `data.elements` with a new array; a subscriber that memoises its inputs (conv. 103) repaints only when a reference changes.
7. **UI prefs and URL state are different things.** UX preferences go to localStorage (`src/core/ui-prefs.ts`); navigation state goes in the URL hash. Do not conflate them.
27. **The sidebar toggle's label reads URL plus registry, never `state.active`.** `state.active` fills in only after `activateWorld`'s slow disk work, so reading it lags the click by about half a second; `registry.worlds.find(w => w.id === route.worldId).name` flips the label in the same frame. Same principle for any UI whose identity should match the URL. `activateWorld` clears `data.elements` and the selection and navigates BEFORE the disk work for the same reason; failure paths restore the prior hash. The mode buttons' active state reads `state.ui.sidebarMode`; the label reads URL plus registry: two reads on purpose.
37. **Sidebar mode and room are independent.** `state.ui.sidebarMode` is UI state persisted through `ui-prefs`; toggle clicks update state, never the URL. Room navigation (the strip and room URLs) is orthogonal. `activateWorld` is room-stable (`src/sidebar/worlds-sidebar.ts`): the current room kind follows to the new world at its landing level, settings keeps its tab, element and map routes fall to home; it never touches the sidebar mode. The `/elements` route survives for old bookmarks and resolves to home. (S223)
44. **The writing icon restores the last narrative.** `WorldRegistryEntry.last_writing_narrative_id` is written whenever the writing room's active narrative changes (deferred with `queueMicrotask`). The room nav's writing icon reads it and navigates with `writingHashForNarrative(worldId, id)`, which emits the short `#/w/<id>/writing/<narrativeId>` URL (`src/middle/writing-helpers.ts`; the `elements` argument is unused). A missing narrative falls back to the bare writing route. With the element-detail scroll memory, returning restores selection and scroll.
46. **The writing room derives its target from the URL, never from `state.ui.selectedElementId`.** `getSelectedElement` in `src/middle/element-detail.ts` returns `route.narrativeId` when `route.mode === 'writing'`, else `route.elementId ?? state.ui.selectedElementId`. The writing room MUST NOT patch `selectedElementId` on narrative navigation: that global selection persists across rooms and feeds the conv. 45 chip. The writing tree highlight also reads the URL. **Related**: the Esc deselect (conv. 32) does not fire when the hash contains `/writing`, `/knowledge`, `/share` or `/import` (`src/core/hotkeys.ts`, `deselect-to-home`); those rooms own their keyboards, and in the Data room Esc would destroy an unsaved pasted payload. (S226)
66. **`defaultCreateType` is a `ui-prefs` pref, not URL or registry state.** The element-create modal preselects `loadUiPrefs().defaultCreateType` when opened without an explicit type; it is set in Settings → Elements (`src/middle/settings-elements.ts`). The modal re-validates it against the offered types, so an excluded default falls back to the first offered type. `ui-prefs` setters load, merge and save (`{ ...loadUiPrefs(), <field>: v }`) so a new field never clobbers its siblings.
95. **Leaving a world flushes the rooms first.** A room with a debounced save registers its flush with `src/core/leave-flush.ts` (`onLeaveWorld`); every flow that swaps the active world awaits `flushBeforeLeavingWorld()` BEFORE it clears state or closes the store. A new room with a debounced write must register, or its last keystrokes die on a world switch. (S360)
98. **Swapping the active world releases the prior world at the COMMIT point.** `releasePriorWorld()` (flush rooms, close the store, clear the slot) runs right before the registry flip in every world-swapping flow (create, import as new, link, tour), never before the flow's fallible work, so a cancelled or failed link never leaves the UI on a world with no store. (S361)
109. **A room instance belongs to one world.** `src/app.ts` remounts the middle room when the active world changes, not only when the room kind does: rooms read world files once at mount and write whole lists back, so a Charts room carried across a switch wrote world A's charts over B's. The room-stable switch (conv. 37) keeps the KIND. Chart writes are read-modify-write of the file (`mutateCharts`). (S364)
115. **Two tabs, one registry.** Every tab holds the whole registry, so a plain save put back a stale copy of a world another tab had changed. `saveRegistry` (`src/registry/registry.ts`) merges against `tabBase`, this tab's view as last loaded or saved: an entry or top-level field this tab did not change comes from storage as it is now; inside an entry this tab DID change, the same rule runs per field; a world another tab added is kept, one it forgot stays forgotten; the same field changed in both tabs: the later save wins. A `storage` listener (`app.ts` → `adoptStoredRegistry`) folds other tabs' saves in and re-bases. Nothing merges against an empty registry (a save after "clear site data" does not resurrect worlds); an unreadable stored value is written over whole. `loadRegistry` re-bases and is BOOT-ONLY; a mid-session reader uses `getState().registry`. Limit: localStorage has no compare-and-swap, so two saves in the same millisecond can still lose one field. Tests: `tests/unit/registry-merge.test.ts`, `tests/unit/registry-two-tabs.test.ts` (`tests/setup.ts` resets the base per test). (S365)
121. **A reload after an update saves first, and only waits so long.** Every reload Atlas causes goes through `reloadAfterFlush` (`src/core/reload-offer.ts`): the rooms' saves (`flushBeforeLeavingWorld`), bounded by `RELOAD_FLUSH_LIMIT_MS` (5 s), then the reload. The PWA plugin's `onNeedReload` hook routes through it, because once a new version takes control EVERY open tab reloads, the ones that said "Later" included, and the plugin's default was a bare reload. A tab from before a deploy asks for code files the deploy replaced; Vite reports each failed lazy load as `vite:preloadError`, answered by ONE banner (offline-aware wording), never cancelled, so the caller still sees its error; a door that toasts its errors skips `isCodeLoadError` ones. The edge half (a missing `/assets/*` must be a 404, not the app page) is Boss's. Guard: `tests/unit/offline-reload.test.ts` (the plugin hook through `tests/fixtures/pwa-register-stub.ts`, aliased in `vitest.config.ts`). (S366)

## U. Shell and UI

3. **Never mutate a shell pane.** Renderers wrap content in a child div and never set `.atlas-middle` or `.atlas-right` cssText or className: touching the pane wipes its `flex: 0 0 X%` and breaks the layout.
4. **`min-width: 0` on flex children.** Without it, wide content pushes the parent past its flex basis.
6. **Acronym-aware field labels.** `humanizeFieldName('image_url')` gives `Image URL` through the ACRONYMS set (URL, ID, API, UI, IP, HTML, HTTP, DNS, UUID, SDK, PIN, GPS; `src/middle/element-detail-fields.ts`).
9. **Visibility by CSS class and `data-active`, never inline `display: none` toggled from JS.** Use an opacity transition on a class; inline toggles are debug-hostile.
10. **Pane scroll is preserved across re-renders.** A module-level `Map<contentId, scrollTop>`, captured before the re-render through a data attribute, restored in a microtask.
16. **Modal chrome lives in `BaseModal.buildModalShell`.** Every modal shares one overlay, panel, title and body through `buildModalShell({ title?, panelClass?, dataModal? })` (`src/ui/modal-base.ts`); the title is optional for a custom title row. A new modal MUST use it. Close discipline: a full outside click only (pointerdown AND pointerup on the backdrop), and Escape closes the topmost modal only.
18. **Element-detail scroll is preserved across re-renders** with a module-level `Map<elementId, scrollTop>`: captured before `target.innerHTML = ''`, restored in a microtask, tracked by a passive scroll listener, reset on world switch (`resetElementDetailScrollMemory()`). Without it a field edit throws the user back to the top.
29. **Hotkey actions never import editor modules.** "Save the active editor" dispatches the `atlas:save-request` DOM event (`SAVE_REQUEST_EVENT` in `src/core/hotkeys.ts`); each editor listens while open. The dispatcher stays independent of the UI's module structure. (Numbered in the atlas-tool skill before this file existed.)
30. **Sentence case for user-visible strings, acronyms preserved.** Every title, label, button, placeholder and toast starts with a capital, and only the first word does ("Birth date", "Image URL": `humanizeFieldName`). The house rule since the Captain's B1 (h63 #8074, 2026-10-20: "sentence case everywhere", one rule for every OnlyWorlds tool, Studio `style/RULES.md`), which retired the landing's lowercase doors and the room strip's lowercased names (1.59.1, Seethe's OW Style pass). Lowercase stays only for what reads as a value, not a label: element type names as identifiers, small state tags ("live", "edited", "revoked", "not published") and unit words shown as values (the calendar builder's "year", "day"). The one word for signing in is "Sign in". A search over labels lowercases both sides (the command palette, 1.32.0), so a label's case never decides what a query finds. (Zero em-dashes in user-visible copy: the voice law.)
153. **A button's class is its rung on the house ladder.** OW Style's ladder (Studio `style/RULES.md` section 8, numbers in `style/control/ladder.json`; the Captain's "looks good", h63 #8314): `atlas-btn-entry`, the solid fill, is one per screen at most and only where someone begins (the first screen's Start a world, the re-link screen); `atlas-btn-primary` is Standard, the everyday default (save, create, confirm, the demo door); `atlas-btn-ghost` is Quiet (cancel, back, toolbar actions), a neutral edge as keel's Quiet wears; `atlas-btn-link` is the link. A confirm dialog is Standard plus a Quiet Cancel, never the fill. A button that deletes or forgets data adds `atlas-btn-danger` (Standard in the danger colour); one that only forgets a link or a sign-in stays Quiet. Inside the rooms the rungs keep Atlas's compact size; the front door takes the ladder's full shape (36 high, 6 round, 14px). Ink on the fill is `--atlas-on-accent`. Guard: `tests/e2e/button-ladder.spec.ts` (both themes, red with the CSS or the classes reverted). (S442)
31. **The middle pane is a flex column: room nav strip plus content.** `app-shell` splits the middle into `shell.middleRoomNav` (40px, top, fixed) and `shell.middleContent` (flex 1). The strip mounts to the first; every room (welcome, home, element, writing, timeline, knowledge, share, import, settings) mounts to the second. With no world the strip shows its labelled preview; it is hidden (`data-active="false"`) only on the welcome branch of an active world (`src/app.ts`). **Renderers never touch `shell.middle`** (it would break the column); they target `shell.middleContent`. This extends conv. 3.
32. **Esc clears the selection and goes home.** With an element selected and no modal, popover, inline editor or pin placement active, Esc clears `selectedElementId` and navigates to `homeHash(worldId)`. The handler checks `!hasOpenModal()` and every non-modal overlay so it never steals Esc. Re-clicking the selected row does NOT deselect: Esc is the one deselect. Room exceptions: conv. 46. **Navigate first, then clear**: every state tick mirrors a route's element into the selection (`app.ts`), so a clear made while the route still names the element came straight back; Esc and the chip's × on an element page both did, until S388 (#175; guard `tests/e2e/selected-chip.spec.ts`, both rows red at the old order).
40. **The writing room takes over the sidebar.** When the route is `writing` and `state.ui.sidebarWritingOverride` is false, the sidebar body shows the writing tree (`mountWritingBody` in `src/sidebar/writing-sidebar.ts`). Clicking the mode toggle sets the override until the route leaves and re-enters writing or the writing icon is clicked. The two-band header mirrors the elements sidebar exactly, and the bands and tree append straight to `.atlas-sidebar-content` so the scrollbar gutters line up. (S224)
41. **`.atlas-middle-header` is locked at 36px.** Every height channel (`height`, `min-height`, `max-height`, `flex: 0 0 36px`) is set with `!important`, plus `overflow: hidden; flex-wrap: nowrap` and `.atlas-middle-header > * { max-height: 100%; flex-shrink: 0 }`. Writing-tier badges and child-create buttons live inside it. One stable band across all rooms.
42. **Optimistic close on popover saves.** `openFieldEditPopover` calls `cleanup()` BEFORE awaiting `opts.onSave`, then surfaces a rejection as a toast. Saves whose failure is rare and survivable never block the UI. The same principle orders "save the registry first, then promote" in `writing-setup.ts`.
45. **The selected-element chip on the room nav strip.** While `state.ui.selectedElementId` is set, the strip's right edge carries `.atlas-room-nav-selected`: `[icon] [name, truncated at 22 chars] [×]`. The body navigates to the element; × clears the selection. `.active` is added only when `route.mode === 'element'`, so something is always highlighted. Icon and × are scoped under the chip for specificity over `.material-symbols-outlined`. (S226)
58. **The Context tab is permanent and route-driven.** It sits at index 0 of `state.ui.rightTabs` for every world (`src/tabs/right/context-tab-lifecycle.ts` enforces it). Its subject comes from the URL through `resolveSubject` (`src/tabs/right/context-tab.ts`): the open narrative, element, focused chart element, knowledge entry or knower; on landings it anchors on an example (the most recently edited writing narrative, the most connected dated element, the most widely held knowledge entry, a page's first carded element); home, settings, data, map routes and the pages list show the empty state. The full table is in DESIGN_SHELL. The subject is never stored on the tab ref; in-pane clicks stay pane-local. (S231)
59. **Context pane prefs flow one way**: registry to orchestrator to graph to toolbar. Toolbar callbacks only persist through `patchWorldEntry`; the orchestrator's `syncPrefsToGraph` diffs against the last applied prefs and propagates. Settings edits ride the same path: one source, one channel, no duplicate-update races.
60. **Diff-aware setter calls, in order, for graphs with sims.** A setter with side effects (`setHiddenTypes` re-runs the physics sim) is not a no-op when called with the same value: it wobbles the layout. `syncPrefsToGraph` calls a setter only when its field changed, and setters that set flags others read (`setLockLayout`) go first.
61. **Browser-default mouse buttons need window-level capture.** To suppress back/forward (buttons 3 and 4), listen to `mousedown`, `mouseup` AND `auxclick` on window in the capture phase and preventDefault all three, scoped with `host.contains(e.target)`; act on `mousedown` only.
62. **Per-ring caps keep multi-hop graphs readable.** Hop depth 1-4: ring 1 is capped at 60 since S367 (a map's backlinks are every pin and marker on it; the cap applies after the type filter and the legend says how many were left out, and an unchanged node set reuses its layout); ring 2 is capped at 12 (6 for a chapter, 4 for a book under tier density), ring 3 at 8, ring 4 at 6 (`RING_CAPS` in `src/tabs/right/context-pane-graph.ts`), each ring scored by edges back to the previous one.
63. **CSS and JS sharing a magic number get a paired constant.** When CSS sizes a special node (`.is-center` 44px over the default 36px), the JS uses `NODE_DIAMETER` and `CENTER_NODE_DIAMETER` with a "MUST match CSS" comment and one `diameterFor(node)` helper at every position site.
64. **Settings tabs are grouped by scope; `editor_settings` is the element-editor pref home.** `SETTINGS_TAB_GROUPS` (`src/core/router.ts`) splits the rail into atlas-wide (`general`, `onlyworlds`, `storage`, `elements`, `maps`) and per-world (`world`, `writing`, `context`); per-world tabs disable with no active world. `storage` holds the atlas folder and sync sections. The `elements` tab is the home for element-editor display prefs stored in `registry.editor_settings` (`field_edit_mode`, `refs_group_by_field`, `confirm_before_delete`, image display, `hide_empty_fields` (S388, #24; the rule is `src/middle/filled-fields.ts`, shared with the tour's sparse pages, and the page carries its own switch under the fields)). When a route key is renamed or merged, add old to new in `LEGACY_SETTINGS_TABS` (`editing` now aliases to `elements`, `account` to `onlyworlds`) so deep links and the stored last tab still resolve.
65. **Settings tabs are per-tab `render*`/`wire*` module pairs; `settings-panel.ts` is a thin orchestrator.** Each tab lives in `src/middle/settings-<tab>.ts` (`general`, `onlyworlds`, `storage`, `elements`, `maps`, `world`, `writing`, `context`) exporting `renderXTab(...)` and `wireXTab(...)`; `settings-account.ts` is not a tab but supplies the account block (PIN, email, account token) that the OnlyWorlds tab renders. `settings-panel.ts` owns the nav rail, last-tab restore and dispatch. A new tab = a new module, two switch arms, and a `SETTINGS_TABS`/`SETTINGS_TAB_GROUPS` entry. Per-world handlers use `updateWorldEntry(reg, worldId, patch)`.
80. **The two-tier room header.** A room landing opens with `.atlas-room-header` (a 22px `<h1>` in `--atlas-text`, subtitle, actions row below, sentence-case section headings); a single named entity opens with the compact 36px `.atlas-middle-header` band (back, kind icon, click-to-edit title, actions), and its title IS its name. Big title: you are in a room; compact band: you are looking at one thing. Details in DESIGN_SHELL "Rooms". (S240)
89. **Below a breakpoint a side pane becomes a DRAWER, not a smaller column.** `src/layout/narrow-layout.ts` stamps `atlas-narrow` (1100px and below) and `atlas-narrow-sidebar` (820px and below) on `body`; CSS turns `.atlas-right` and then `.atlas-sidebar` into absolutely positioned drawers over the middle, with a scrim, Escape and hashchange dismissal, one open at a time. Why: the pane floors (180 + 280 + 240 + dividers, about 706px) with every ancestor hiding overflow meant a pane below the floor left the screen with no scrollbar. Three rules: (a) the `!important` on narrow pane widths is load-bearing, because `app-shell.ts` writes widths as INLINE `flex`; (b) a drawer needs an OPAQUE floor (`--atlas-bg`); (c) the drawer toggles live in the room nav strip and are `position: sticky` at its edges. Above 1100px nothing here applies. A fourth tier, the phone (560px and below, S403), is a thumb strip: rooms past Home and Writing fold into More, every strip control is 40px, and the shell is `100dvh`; the left drawer is `min(360px, 88vw)` over a 0.62 dim, its type icons are 40x44 tiles in a grid that fills the drawer, each count under its icon (S404, Seethe's pass); it never applies while touring. Guards: `tests/e2e/narrow-layout.spec.ts` and `tests/e2e/tour-narrow.spec.ts`, the width-aware specs; the rest of the suite runs at one width. (S323)
90. **Canvas chrome does not follow the theme; app chrome does.** App surfaces use `--atlas-ink-rgb` / `--atlas-scrim-rgb`, which FLIP under `[data-theme='light']`. Chrome floating over the map or chart canvas uses `--atlas-canvas-ink-rgb` / `--atlas-canvas-scrim-rgb`, which do NOT: a map's background is the user's artwork, and those canvases are dark islands. The bug class is a foreground and a background answering to different authorities (a flipping scrim with a literal `#fff`; a literal near-black with themed ink). A surface painting its own dark floor under a light app re-pins the WHOLE `--atlas-text*` family. Anything over the user's artwork holds the dark chip in both themes; the charts island keeps its dark plot inside a light-page frame. Guard: `tests/e2e/light-mode-contrast.spec.ts`. (S323) **The light-mode island list** (`:root[data-theme='light'] …` in `atlas.css`, beside the tour and the timeline) is where a dark chip over a light app restates the family: since S437 it holds the zone drawing strip (1.58.1, 1.02:1 before), the waypoint toast and the map's placement hint (1.58.2, 1.07:1 and 1.12:1 before), found by a live frame and a census of every rule under a canvas-scrim floor; each has probes in the spec. A new dark chip joins the list and the spec. Since 1.58.3 the spec composites the text's own alpha over its floor (white at 0.28 had measured as white: the waypoint rider read 18.41:1 and was 2.28:1).
103. **Rooms that render on every notify gate on their inputs.** The element list memoises what its rows read (`listInputs` in `elements-sidebar.ts`: elements, style rules, filters, muted, query, sub-filters, lens, active map, flashing, tour-fresh, loading) and returns early when none moved; a selection-only change moves two classes. The home does the same (`lastInputs`). Anything new a row or the home reads must join its input list or it will not repaint. Measured on Sikelia (12.3k elements): an unrelated notify went from 966 ms to 4 ms. (S362)
113. **Nothing rebuilds under a focused text control.** A background tick (a sync publish, a pull, another room's save) that replaces a focused input removes it; Chromium blurs a removed input and the blur COMMITS, so a half-typed value saved and the rest of the typing landed on the page as hotkeys. Every surface that rebuilds on a tick asks `isEditingIn(root)` (`src/middle/element-detail-header.ts`) and defers to the root's `focusout` (element editor, writing header, knower page); `editable-title`'s `sync()` keeps the same rule. (S364)
119. **Whatever points into a drawer opens it.** Below 1100px and 820px the side panes are closed drawers (conv. 89), so anything that sends the user to a pane must show it: a tour step opens the pane its control or subject lives in (`src/tour/tour-pane.ts`: pure `tourPaneFor`, applied by `tour-bar.ts` only when the answer CHANGES, so a hand-closed drawer is not fought); arming pin placement opens the map drawer (`map-placement-hint.ts`); the no-world screen opens the sidebar once per stretch, never during the tour, one task after the navigation that brought it up (`welcome-panel.ts`); **during the tour the tour owns the drawers**: the drawer layer's close-on-hashchange stands down while `atlas-touring` is set, because every step navigates and that close, landing a tick later, shut the pane the step had just opened (gate B1); the preview strip (no world open) carries the sidebar toggle; during the tour a toggle shows once the tour has revealed its pane. Copy that says "top left" or "the map pane" is a behavioural claim at every width. Guards: `tests/e2e/tour-narrow.spec.ts` (hit-tested reach at 800 and 1000 through steps 2, 3, 6, 7, back to 6, every mint of 8, 14 and the finale: Playwright counts off-screen as visible), `tests/unit/tour-pane.test.ts` (the table over the real steps), the no-world row in `tests/e2e/narrow-layout.spec.ts`. ## F. Folder and disk

11. **The FolderStore stamps `local_updated_at` on every write.** Callers never set it. Only sync code stamps `server_updated_at` (the engine, the initial download, Make Online); the store preserves it on round-trip.
12. **Tombstones append before the file is unlinked.** If the process dies mid-delete, the tombstone survives and the next sync still pushes the delete (`appendTombstone` before `unlinkElement` in `src/store/folder-store-fs.ts`).
13. **One writer at a time per folder.** The lock (`.atlas/lock`, `{ tab_id, started_at, last_heartbeat }`) is refreshed every 30 s by the owning tab. A lock older than 90 s is stale and is taken. A live lock refuses the open: `claimLock` throws `ELockHeld`, and `activateWorld` offers a consented take-over (a confirm naming how long ago the other tab was active; yes reopens with `forceTakeLock`, no abandons the open and restores the prior URL). The silent boot path never prompts. There is no read-only mode (the `folder-store-fs.ts` header comment still claims one). A parked store stales its own heartbeat so another tab can take the world at once.
14. **Element files are the schema.** The `type` field on disk is authoritative. The adapter re-stamps `type` from the path on every server record (the v2 wire returns it too, so this is a same-value overwrite); a folder file WITHOUT `type` gets it from its directory at index time.
28. **Filenames** (numbered in the atlas-tool skill together with 87; the rule is conv. 87 and the DESIGN_FOLDER "File naming" table).
43. **Narrative deletes cascade through `parent_narrative` chains.** `findDependents` for a narrative walks the chain breadth-first and collects every descendant narrative plus every pin on the target or a descendant; `deleteElement` tombstones them in dependency-safe order. Otherwise deleting a book orphans its chapters as loose roots. The count appears in the confirm. Implemented in both `folder-store-fs.ts` and `tests/fixtures/mock-folder-store.ts`.
79. **Element writes serialize per id at the FolderStore boundary.** `updateElement` and `deleteElement` queue through `PerIdWriteChain` (`src/store/write-chain.ts`) in BOTH stores: same-id operations run in submission order, different ids stay concurrent. It kills the lost-update class (two read-merge-writes interleaving) for every caller; a delete queued behind an update waits for it. It cannot fix a patch COMPUTED from a stale snapshot: read-compute-write callers still need await discipline (conv. 77) or `updateElementWith`. The mock yields a microtask between read and merge so an unserialized regression shows in vitest. Tests: `tests/unit/write-chain.test.ts`, `tests/integration/folder-store.serializedWrites.test.ts`, the concurrent-update case in `folder-store-fs.spec.ts`. (S238)
87. **Filenames: sticky runtime writes, a converging background tidy, lowercase equivalence.** The full contract is the DESIGN_FOLDER "File naming" table (the Folder Format spec source). The load-bearing halves: (a) a RUNTIME write keeps the file's current name whenever it is any valid form for the element's name, compared by `sameFsName` (lowercase): on case-folding filesystems (NTFS, APFS) a case-variant pair is ONE physical entry, so write-new plus delete-old would destroy the file, and OPFS-based tests cannot see this; (b) the tidy is the ONLY converger: id-sorted (deterministic layouts), a FULL occupancy view computed before any write, never touching unreadable files, run in the background after first index. The index is built from file BODIES; `parseIdFromFilename` is diagnostics, never identity. Tests: `tests/unit/fs-utils.slug.test.ts`, `tests/e2e/folder-store-slug.spec.ts`.
91. **The union read.** `elements/<type>/` is the format for all 22 types; `spatial/{map,pin,zone,marker}/` is a legacy path atlas up to v1.0 wrote. Atlas reads both and merges, writes every new element to `elements/` (never creating `spatial/`, also in a folder with legacy files: spec v0.3.8 §4, S421), and rewrites each element where it was found (`fileIndex` carries a `layout`). Cross-layout twins serve the `elements/` copy, are warned about, and are never deleted. `elementDirSegmentsIn(layout, type)` forces every caller to name the layout. Full table: DESIGN_FOLDER "The union read". Guards: `tests/e2e/folder-store-fs.spec.ts`, `tests/e2e/folder-conformance.spec.ts`. (S334)
92. **Every write merges into the file as it is ON DISK, not as cached.** `FsFolderStore.readForWrite` re-reads the file inside the per-id chain (conv. 79) for `updateElement`, `updateElementWith`, both sync stamps and the background filename tidy (S386, #89: it wrote the scan's cached body under the new name and removed the old file, so an outside edit landing between scan and tidy was lost, and a file with conflict markers was replaced; guard `tests/integration/folder-store.tidyReadsDisk.test.ts`, red at the old code), falling back to the cache only when the file vanished (a file that will not parse throws `CorruptFileError` and is never written over, conv. 99). A field another tool changed in the file survives atlas's save. Scope: this keeps outside edits ALIVE; SHOWING them is conv. 111; whether they SYNC is still decided by the in-file stamps (the manifest question: `Forge/Notes/2026-09-28-shared-surface-design.md`). Guard: `folder-store-fs.spec.ts` "a field edited in the file by another tool survives". (S359)
101. **A delete removes the dead ids from every link that named them** (keel parity: `_scrub_cross_type`). `src/store/scrub-links.ts`: after a non-silent `deleteElement` (both stores), every other element's schema link fields drop the primary and cascaded ids (a single link to `null`, a multi link filtered), each referrer through its own chain, so a synced referrer pushes the cleared link. Silent deletes (the engine's server deletes, Route 2's swap) never scrub. A pin's `element_id` is the cascade's, not the scrub's; prose is user text. Links already dangling in a LOCAL world are offered for removal in Settings → World (`findDanglingLinks`); a linked world's absent id may just not be downloaded yet. (S362)

Top-level strings and string arrays by equality except identity, stamps and prose (schema text fields get only the `ow://` rule); `ow://` links in any string; the TipTap sidecar (object or JSON string): `elementChip` and `mention` `attrs.id`, `link` marks with an `ow://` href; `atlas_page_blocks` walked RAW by kind (unknown kinds untouched, `fullPinIds` included). ## W. Sync and the wire

8. **The spatial disk/wire rename lives in the adapter, schema-derived; the DISK reads both spellings and each file keeps its own.** On disk atlas has written pin and marker links as `map_id`/`zone_id`; the v2 wire and the Folder Format use bare `map`/`zone` (pin's `element_id`/`element_type` are the schema names). `OwV2ClientAdapter` derives the rename from `FIELD_SCHEMA` through `relationFieldsFor`; never hardcode it. `src/store/disk-link-names.ts` (same authority) normalises every body read from disk to atlas's spelling and records the FILE's spelling in `fileIndex` (`spelling: 'atlas' | 'bare'`); every element write goes through `writeElementFile`, which writes the file back in the spelling it arrived with. A file declaring neither (a mapless pin) casts no vote. **Born bare** (Skeld's ruling, S359): a NEW file takes `bare` unless some file of its type already declares atlas's suffix (`bareSpellingTypes`), so a folder atlas creates speaks the format and an old atlas folder keeps its dialect. Cost accepted: atlas older than 1.3 reads a bare pin as mapless. Same law as the union read: read both, never migrate a key as a side effect of opening, write back what was there. Fixture v1.2.0 carries a bare-spelled pin. (S354)
15. **One engine, attached at world activation.** `attachSyncEngine` is a module-level singleton: at most one `SyncEngine` exists. Switching worlds detaches the previous engine (`stop()` cancels timers, the slice resets), so pushes never cross worlds.
17. **UI folder writes call `requestPushIfLinked()`.** After any successful create, update or delete from a UI handler, call it so the autosave debounce fires; it no-ops for local-only worlds. Without it an edit to a linked world would not sync until something else pushed.
19. **Pin writes require `element_type`** (a server rule). Every path that creates a pin populates `element_type` from the referenced element (map placement looks it up in `state.data.elements`; the contextual create gets `(id, type)` from `ElementCreateModal.onCreated`). `pushPhase` self-heals a legacy pin missing it before the create. Both fakes enforce the rule.
21. **Clear fields with `null` (relations, numbers) or `''` (text), never `undefined`.** `JSON.stringify` drops `undefined` keys at the disk write AND on the wire, and a PATCH treats a missing key as "no change", so the server would keep the old value. UI sites that mean "clear" pass the right sentinel: the single-link × in `src/middle/element-detail-fields.ts` and the empty-input handling in `field-edit-popover.ts`. The fakes strip `undefined` like the JSON wire does (conv. 20). Test: `tests/integration/sync-engine.fieldClear.test.ts`.
22. **An auth failure bails the round and turns the engine red.** On 401/403 the engine (a) stops iterating, (b) sets `paused` so the debounce stops firing at a dead endpoint, (c) goes to `{ kind: 'error', recoverable: true }`. `SyncResult.auth_blocked` (refined by `auth_reason`: `key_revoked`, `read_only_key`) makes `sync-attach` show a dedicated toast. Recovery is a fresh engine (a PIN change re-attaches). Without it the pill said "synced" while nothing reached the server. Test: `tests/integration/sync-engine.authBlocked.test.ts`. **Not every 403 is the key** (S385, #104): keel's member refusals, `not_author` (a contributor changed someone else's element) and `owner_only` (a member changed the world's own settings), are about one item; `memberRefusal` keeps them out of `isAuthError`, so they are per-element or world-step failures (kind `not_yours`, the issue line says whose it is) and the round goes on. Guard: `tests/integration/sync-engine.memberSeat.test.ts` (revert-checked: three red with the carve-out removed).
23. **CREATE batches go through `/bulk`: one atomic request, server-resolved order, cycles included.** `pushPhase` (and Route 2's merge) route never-synced batches of two or more through `POST /bulk`; keel resolves in-batch links as a fixpoint, so cyclic webs land in one round-trip. Protocol: atomic, one retry of the survivors on a partial failure, timestamp backfill (never the client clock); SYNC_NOTES "/bulk CREATE path". The Kahn topo-sort (`sortCreatesByDependencies`) survives only as the fallback orderer. Tests: `tests/integration/sync-engine.bulkPush.test.ts`, `tests/integration/sync-engine.createOrder.test.ts`.
24. **Unlink severs the sync history: `resetSyncBaseline()` is not optional.** Every element's `server_updated_at`, every pending tombstone, sync-state (`last_*_at`, conflicts, server deletes, cursor, meta baseline) and `world.json.api` are cleared. Otherwise a later Make Online Route 1 treats every element as an UPDATE against the new world, every pre-update GET 404s, and the new world looks online but empty. The unlink handler calls it AFTER `detachSyncEngine()` and BEFORE the registry write. "Forget world" is different: it drops the registry entry and leaves the folder, sync history included. Test: `tests/integration/folder-store.resetSyncBaseline.test.ts`.
25. **Flush-on-attach runs BEFORE pull-on-activate.** Both come from `attachSyncEngine` and share the engine's `inFlight` promise, so racing them made the flush silently return the pull's result and stranded edits. One async chain awaits the flush, then the pull: pending writes are older user intent and land before a pull looks for newer remote changes. The flush is unconditional when anything is pending (above 50 changed elements it holds and asks, conv. 117); the pull is opt-in. Test: `tests/integration/sync-attach.flushBeforePull.test.ts`.
26. **The engine preserves `last_sync_at` across pause and resume.** It keeps a private `lastSyncAt` updated on every idle transition, and `resume()` publishes it, so the pill never flashes "never synced". Test: `tests/integration/sync-engine.resumePreservesLastSyncAt.test.ts`.
86. **Sync-state mutations go through `updateSyncState(mutate)`.** Every patch computed FROM the current sync-state (conflict and server-delete list edits, dedupe-appends) uses the mutator, which receives the CURRENT state inside a store-global chain. Never split it into `readSyncState()` plus `writeSyncState()`: a whole-array patch computed from a snapshot taken before network I/O clobbered a concurrent round's entries. `writeSyncState(patch)` stays for whole-field replacement on the same chain. Test: `tests/integration/folder-store.syncStateChain.test.ts`.
96. **A sync stamp keeps an in-flight edit dirty.** Push sites pass the `local_updated_at` the sent body carried to `stampServerUpdatedAt`; `src/store/sync-stamp.ts` lifts `local_updated_at` just past the new baseline when the file changed during the request. Any new push path must pass it (Route 2's creates do since S367). A stamp of `null` means "the server holds different content": a create adopted after a lost response keeps the element dirty when the bodies differ (`adoptServerCopy`). A future manifest must hash the body that was SENT. (S360)
99. **Every element write is chained, pull-apply included.** `applyServerRecord` runs in the per-id chain; the pull's race check is `applyServerRecordIfUnchanged(..., expectedLocalUpdatedAt)`, check and write in one slot, reading the disk stamp. `resetSyncBaseline` clears per element through `clearServerBaseline`. Reads whose result is diffed or sent use `readWorldMeta({ strict: true })`; a `CorruptFileError` in a round pauses the engine with the file named (`settleThrownRound`). (S361)
100. **A busy, rate-limited or unreachable server ends the push round.** `isTransientError` (429, 503 `server_busy`, fetch's network TypeError) sets `transient_blocked`; nothing pauses, no baseline moves, one retry after `Retry-After` (`OwV2Error.retryAfterMs`, default 30 s, `TRANSIENT_RETRY_DEFAULT_MS`), one plain toast. Auth stays its own bail (conv. 22). (S361)
107. **The engine can be HELD** (`SyncEngine.hold()`). A counter separate from `paused`: it clears the timers, waits for the round in flight, and nothing reaches the server until the release; `resume()` cannot release it, and a release cannot clear a user, auth, network or corrupt-file pause (their state is republished). `held_for` says why (`rekey` or `disk`). The `online` listener asks `isNetworkPaused()`, never the pill. A round that ends during a hold leaves the state to the hold. (S363)

117. **The big-batch question at open** (`flushPendingOnAttach` in `src/sync/sync-attach.ts`, `holdBigBatchAtOpen` in `src/core/live-folder.ts`). 128. **The raw-error ratchet has one exemption, and it must say why.** A line in `src/` that reads an error's text for a RECORD or a CLASSIFICATION (a failure's internal message, a console object, a check on a known browser string), never for a person, ends with `// raw-error-ok: <why>` and is not counted by `tests/unit/no-raw-error-in-copy.test.ts`. 20. **Encode a real-server validation rule in the fakes BEFORE fixing the caller.** When live OnlyWorlds returns a 4xx the fakes did not catch, first add the rule to the MSW handlers (`tests/msw-handlers.ts`) AND `FakeOwApiClient` (`tests/fixtures/fake-ow-client.ts`), then fix the caller. The fix lands with a regression test, and future code breaking the rule fails at once. This is how the fakes stay faithful without contract-testing infrastructure.
