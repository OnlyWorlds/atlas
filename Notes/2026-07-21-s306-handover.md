### 4. The NUL byte (infrastructure, worth its own line)

`calendar.ts` used a raw `'\x00'` as an empty-token sentinel. A NUL makes
ripgrep classify the file as **binary**, so every content search over 704 lines
of load-bearing calendar logic silently returned nothing — while `--count` still
returned a plausible number, which is worse than an obvious failure. Replaced
with `EMPTY_KNOWN = ''` (private use, written as an escape so nothing
invisible sits in the source). **Grep reads the file now.** Any future sentinel
here must stay non-NUL; the comment says so.

## The honest flake

The full e2e is **exit 0 / 249 passed**, but the two long tour walks are
**flaky** (fail then heal on retry). Both are my new gesture. Recent sessions
reported zero-flaky, so this is a small regression in suite quality, not
nothing.

**Mechanism, measured rather than guessed**: `handleKeyDown` promotes the
decoration containing the CURSOR, so the Tab only lands once the click's
selection has actually been applied. Waiting on `ProseMirror-focused` is NOT
enough — it resolves from a cached snapshot without a round-trip, and the key
then arrives before the selection exists. Every green I got before understanding
this traced back to some incidental round-trip buying the time. The helper now
waits on the selection sitting inside an `.atlas-autolink-hint` and retries the
click+Tab pair; the dedicated test is stable at `--repeat-each=3`, the long
walks still occasionally need the retry.

**The fix if it annoys anyone**: give the two WALK tests a deterministic path to
satisfy the gate (the precedent is `movePinToSwamps`, which forces coordinates
through the store because the raw click mapping "is not what these specs
assert") and keep the real click+Tab in the dedicated writing-beat test, where
the gesture is the subject. I did not do this because a store write while the
editor is open is reverted by the editor's next save — it needs the live-editor
ops, which is a bout of its own.

### 5. The palette lift (the survey's #1 finding, built + gated)

`roomOf` and the desk click-through moved out of `world-home.ts` into
**`src/core/element-room.ts`**, and the command palette now routes through it.
Before: every non-room result ended in a bare `navigate(elementHash(...))`, so
Cmd+K on a map, a page, a knowledge entry or a chapter landed in the generic
field editor — the app's only global jump flattening four rooms, while the home
twenty lines away resolved them correctly. Same shape and reason as
`core/element-search.ts` (S258): the shared language moves to core so the
surfaces CANNOT diverge.

**e2e revert-checked**: the new spec fails with the old bare-hash behaviour.

**The close gate (2 opus lenses) earned its keep — one HIGH, confirmed by a run:**
`openMapTab` only mutates right-pane state and never navigates, so from the
palette (global, fires inside the writing editor where focus/reading mode sets
the right pane `display:none`) a map jump produced **nothing observable**. I had
reintroduced the exact dead click the function exists to prevent. Confirmed by
adding a URL assertion and watching it fail, not by trusting the source read.

**And the fix's own first draft was wrong**: making the shared function always
navigate broke a SHIPPED home behaviour — an existing S265 spec caught that
pinning the URL to a map fights the map-index tab switch. The two surfaces
genuinely differ, so the difference is now an explicit `routeToMap` option with
both reasons written down, rather than a silent divergence.

**Two more gate findings folded**: the pinned "Write" desk row hardcoded its verb
while `roomOf` gives knowledge/page precedence over writing (subtype is free
user text, so a narrative can be both) — the row could say "Write" and open
knowledge; verbs and icons now derive from `roomOf`. And the row's `hash` field
had become write-only, computed three times per render and read nowhere.

**The second lens found the fix INCOMPLETE, and it was my own law pointed back
at me.** The palette's "see all →" hands its query to the ELEMENTS SIDEBAR (the
two deliberately share their match language), and the sidebar still navigated
with a bare `elementHash`. So Cmd+K → Enter opened the room, while Cmd+K → see
all → clicking the identical row opened the field editor. Three surfaces ask
this question; I had converted two. Now converted, e2e revert-checked.

**With one deliberate exception, which an existing spec caught**: map rows in the
sidebar keep opening the map's ELEMENT PAGE, not the canvas. A map is the only
type with both a canvas and an editable record, and the sidebar is the
browse-and-edit surface — it is how you reach a map's Image URL field, which is
the real user path the S300 sketch-rescale hook hangs off. Routing map rows to
the canvas silently removed that path. The narratives have no such split, so
sending them to their rooms loses nothing.

**Also banked from this gate (pre-existing, NOT a regression)**: a writing-room
jump can land on the writing SETUP WIZARD rather than the chapter.
`roomOf` routes on `isWritingNarrative` (this narrative has a writing supertype)
while the writing room gates on `isWritingInitialized` (EVERY chain member does).
A world holding both a Book/Chapter chain and an imported foreign-label chain
satisfies the first and fails the second. Recoverable (the narrativeId survives
the hash), but it opens a label-rewriting wizard. The world home has the same
hole. Fix shape: either have the editor honour `route.narrativeId` when the
target is a writing narrative regardless of the flag, or have `roomOf` fall back
to `elementHash` when the world is not initialized.

**Upheld by the gate, worth not re-verifying**: no module cycle forms from
core/element-room (35-module transitive graph, empty cycle set), and nothing
loads earlier at boot — 28 of 29 newly-reachable modules were already in
`app.ts`'s eager graph, and none of them have top-level side effects. Skipping
`selectedElementId` for room-owning elements does not affect what those rooms
render: knowledge/share/writing routes carry their own id fields, so the
selection mirror never applied to them. The `as WorldMap` cast is safe
(openMapTab reads only id and name).

## Banked, with specs

**From this session's survey** (five agents; every claim below re-verified by my
own hand before banking — two of my own earlier banked claims turned out WRONG,
see PROGRESS):

1. **The command palette misroutes every element that owns a room** — the
   critique's #1 and the best value/cost ratio on the board.
   `command-palette.ts:267` ends every non-room result with a generic
   `elementHash` navigate, so Cmd+K on a map, page, knowledge entry or chapter
   lands in the field editor instead of the room. `world-home.ts:50-70` already
   has `roomOf` + `openDeskTarget` doing it correctly (including the subtlety
   that a map needs `openMapTab`, because `navigate(mapHash)` cannot activate an
   already-open background tab). **Spec**: lift both into a shared module
   (`core/element-room.ts`), route the palette through it so the two surfaces
   cannot diverge again. Gate-worthy (shared module, multiple surfaces).
2. **`zone-edit-mode.ts` has ZERO tests at any layer** — 1072 lines wired into
   six files, and `zone-drawing.test.ts` carries a comment claiming coverage "by
   smoke" that is false (grep `smoke.spec.ts` for "zone" → nothing). It rides
   the same coordinate-space transform that already corrupted pin y-coords at
   S300 (the sketch-rescale contract scales pins AND zone markers), plus a
   second transform in vertex-drag that no test has ever driven. **This is where
   I would look first for a live bug.** Its own session.
3. **`applyChart` is a one-way ratchet** out of the calendar default (writes an
   explicit `null`; no UI path back to never-chosen).
4. **Clearing `now` bounces the tour narrator** from phase b back to phase a.
5. **The selection bubble is not wired into the writing room** (share-only), so
   link-to-existing there is buried in a right-click menu. Trap: the bubble
   binds listeners at construction and the writing room remounts its editor per
   narrative, so it must be destroyed/remounted per narrative.
6. **The reverted chart-framing fix** — full redo spec is in the S305 handover
   addendum, unchanged and still correct.
7. **A home/charts regression test** — I fixed the mismatch but did not guard
