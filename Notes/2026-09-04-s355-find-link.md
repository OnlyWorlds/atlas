**2026-09-04 11:32** · a Discord feature request, reframed against what the writing room already had, shipped at both tiers.

## The request, and the reframe

mika (Discord, 2026-09-03): "search narrative text (kinda like a ctrl f?) for keywords and be able to link all of them to a specific element". The thread's own pushback (one link per section is the norm; pronouns are ambiguous) is already encoded in atlas as the first-mention rule, so the answer was not to loosen that rule but to add a second, deliberate gesture beside it.

What existed: select text, right-click, "Link to existing element" (one occurrence, teaches the alias); link-all (every element, first mention only); Ctrl+F/Ctrl+H find and replace (text only). And Captain's screenshot found the real shape: chapters and books open in the COMPILED view, which had no editor and so no find at all.

## Shipped

1. **Scene tier**: "Link to element…" in the find bar. Type the word, pick the element, every match becomes a chip in one undoable transaction. Word saved as alias when foreign.
2. **Compiled tier**: find works on the rendering (`writing-compiled-search.ts`), Ctrl+H opens find there (nothing to replace in a rendering), and "Link to element" writes every match across root + descendants on disk, then re-renders the view.
3. **Fixed on the way**: Ctrl+F after switching scenes inside the room opened a detached bar (orphaned by `root.innerHTML = ''`).

Files: `core/prose-autolink.ts` (kernel: `buildTermScanner`, `linkTermMarkdown`, `linkTermRichtext`), `writing-workspace-search.ts` (imports the shared scanner), `writing-workspace-editor.ts` (`linkAllMatches`, `linkTermInEditor`), `writing-workspace-find-bar.ts`, `writing-compiled-search.ts` (new), `writing-bulk-link.ts` (`bulkLinkTerm`), `writing-live-editor-ops.ts` (`linkTerm`), `writing-workspace.ts` (proxy routing, link flow, remount, readOnly hotkeys, detached-bar rebuild), `prose-link-existing.ts` (export), `help-content.ts`, `atlas.css`, changelog 1.4.
