## Facts the next bouts need (dug and verified this session)

- **Writing tiers are hard-coded four** (`l1..l4` in `writing-helpers.ts`; the setup screen validates all four labels). "Choose two" is a hide-fields job with the other two prefilled, not a configurable count.
- **Chapter 1's prose ships with links already baked** as `ow://` markdown. The "link three words yourself" beat needs an unlinked variant in the bundle.
- **The gate signal for linking** already exists: `countChips(view)` with no range, in `writing-workspace-autolink.ts`.
- **The selection bubble is NOT wired into the writing room** (share editor only). Right-click linking is; the bubble is not.
- **The charts room has no tour branch at all** and its controls mostly lack `data-action` hooks (type chips, set-now, focus pill, gallery cards are class-only). Highlighting them needs attributes added first.
- **The undated rail has no predicate seam** — it scans all elements globally. Filtering it to one named item means adding a parameter or hiding it in CSS.
- **Scroll mode has no rail, no drag-to-date, no now-setting.** Hide the canvas/scroll toggle during the drag beats or the gestures we just taught vanish.
- **The bundle ships `time_current: 15` and event dates 7 and 12.** Drop the now so the user can set it; trim the dates if the user is meant to date them.
- **Two eras on one line is already supported and unit-tested** (`CalendarEra.direction: 'up'|'down'` sharing a pivot, the Dune B.G./A.G. pair). Nothing to build. The bundle has NO calendar element today.
- **Calendar-worded date entry exists only in the charts drag popover**, not on element pages. Convenient for us, and a real product gap worth banking.
- **Resume after exit**: tour state is DELETED on exit today, so `resumeTour` is a no-op after an explicit exit. Rebuild-from-bundle is cheap because almost nothing is user-authored, but a naive rebuild would stomp the pin's real coordinates with the bundle's baked `221,295`, and hands-on completion is not encoded in the step index. If it gets built: persist `{step, choices}` with a `schema_version`, and hold the invariant that **the record seeds a rebuild and is never consulted during a live tour**.

## Traps (hard-won this session)

- **A source-text fingerprint cannot verify a copy migration.** A regex over string literals cannot tell a literal from an apostrophe in a comment; it produced pure noise. The instrument that worked was a temporary vitest importing the committed table alongside the working one and comparing at runtime.
- **Two awaited Playwright clicks do not reproduce a double-click race.** The first mint has already landed. Dispatch both clicks synchronously inside one `page.evaluate` or the spec passes with the serialization removed, as mine did.
- **A revert-check can be half a revert.** The R1 link assertion survived reverting the write-time strip, because the post-mint heal repaired it. Both had to go before it failed. Neither is dead code; the engine says so at the call site.
- **The full suite catches what the spec file cannot.** Four sibling tour specs walked past the objects step and hung for 45s once it gated on three mints. Per-file runs never saw it.
- **Do not read a spec run as a verdict while a full suite is going in the background.** I did, got a false failure on the OPFS spec, and had to re-run quiet.
- **A copy line that points at a control is a claim about that control's visibility.** The run's copy says "the + above the element list"; the sidebar's own pulse only fires on an empty world, so it pointed at nothing. No test would have caught it. Look at the beat.
