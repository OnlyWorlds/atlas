## The one to read first

**`startTour` assumed a stage instead of establishing one.** Every launch it
had ever been tested against — the landing door, every e2e — arrived with no
active world, no atlas root, and a `#/` route, so the assumption held by
accident for the tool's whole life. The settings replay row breaks all three
at once, and the third break is a hard stop: `worlds-sidebar` tested
`if (root)` before the tour branch, and **finishing the tour is what sets a
root**, so the natural path (finish → replay) had no scripted create button,
no Next, and no way forward.

The general lesson is worth more than the fix: *an entry point that has only
ever been exercised from one starting state has untested preconditions, and
the preconditions are invisible precisely because the happy path establishes
them for free.*

## What shipped

### 1. The replay bug (three leaks, each revert-checked separately)

- `clearStageForTour()` in `tour-engine.ts` — closes the active world,
  detaches sync, clears `selectedElementId` / right tabs / pin placement,
  sets sidebar mode, and navigates off the launching route. `routeFor`
  cannot do this: it is gated on a worldId that is `''` until the create beat.
- `isTouringNoRoot()` → `isTouring()`, and the tour branch is now tested
  **before** the root branch. Order is load-bearing; the comment says so.
- The worlds list filters to `demo === true` while touring. On a first launch
  this was free (empty registry), which is why it never existed.
- The replay control moved to a chip in the settings NAV (Captain's S306
  design), wired in `settings-panel.ts` so it works from any tab.

**The test that had never existed**: `tour.spec.ts` → "replay from settings
with a world open clears the stage and can be completed". No prior tour spec
started with `state.active !== null` or `atlasRoot !== null`, and
`grep "replay-tour" tests/` returned nothing at all.

**A vacuous assertion I caught by revert-checking**: my first draft asserted
the user's world was hidden using `.atlas-worlds-list`, a class that does not
exist — it passed with the fix reverted. Now a present/absent PAIR on the
same real selector (`.atlas-list [data-world-id=...]`), so a markup rename
breaks one half loudly instead of quietly disarming the other.

### 2. Pin uniqueness — one wall at the funnel

`core/pin-uniqueness.ts`: pure `findDuplicatePin` + typed `DuplicatePinError`.
Guarded in **`createElement`** (gated on `type === 'pin'`), not `createPin` —
five paths create pins and the import applier bypasses the wrapper.
`MockFolderStore` mirrors it from the same predicate (convention 20).

Four cascade fixtures now put the second pin on a **second map** instead of a
second character. That is legal under the rule, it is the real-world shape,
and it exercises a cross-map dependents sweep the same-map pair never did.

### 3. Zone edit — the data-loss trio, kernels, and first tests ever

`zone-edit-mode.ts` had **zero coverage at every layer**, and its sibling's
"exercised by smoke" comment was false (`smoke.spec.ts` contains no zone
anything; 34 e2e files, none drive edit mode). That comment is now corrected
rather than deleted, so the next reader learns what happened.

- `abortEditModeForMap` orphaned the persisted snapshot, and its caller runs
  on **world switch**. Edit → drag two vertices (each autosaved) → switch
  worlds → return, and the recovery replayed a "revert" over committed work.
  No undo exists in atlas.
- `exitEditMode` cleared the snapshot under the CURRENT world while its
  comment claimed the session's. `EditSession` had no `worldId` field, so it
  could not possibly have done what it said. Field added, stamped at entry.
- The snapshot was deleted while `restoreFromSnapshot` was still in flight.
  Now cleared in `.finally()`.
- Enter/Escape were captured globally with no target check, so pressing
  Escape to dismiss a field in the zone's still-mounted detail panel reverted
  every vertex drag. `isTypingTarget` is exported so the test drives the same
  predicate the listener does.
- `zone-edit-kernels.ts` (pure): `computeInsertion` renumbers by POSITION —
  index-as-order put vertices on the wrong segment with non-contiguous
  orders, and **always appended on imported zones** where every order is
  absent. `commitVertexPosition` clamps to canvas, asserted for PARITY
  against `scaleSpatialPatches` rather than restating the rule.

**Still open here**: findings #6 (rebuildHandles tears down a handle mid-drag),
#8 (Edit shape picks a map by element-array position, not the active tab),
#9 (cancel recreates deleted markers from a 4-field snapshot, losing any
future marker metadata). All specced in the session log; none is data-loss.

### 4. Autolink: case-insensitive AND case-preserving

**These are one decision.** The index folds keys, the scanner carries `i`, and
every promotion path labels the chip with the writer's own matched text.
Folding alone would have silently recapitalised prose on every lowercase
mention — which was Captain's original complaint, arriving via aliases.

- "THE GUARANTEE" in `prose-autolink.test.ts` sweeps four casings through
  BOTH engines (markdown + richtext). This is the highest-priority property
  of the feature per Captain; it should never be weakened.
- A genuinely different alias ("the duchess" → "Aralia") still resolves to the
  canonical name — a deliberate, separately tested decision. The paired test
  states that boundary explicitly so a future widening of the case rule
  cannot quietly turn into renaming every alias.
- **Trap fixed**: two sites rebuilt the scanner as `new RegExp(src, 'g')`,
  which would have silently dropped the `i`. All sites now read
  `index.scanner.flags`. A test that restated `'g'` was measuring a matcher
  the app no longer had — that is how the tour's linkable-count test failed
  for a reason that had nothing to do with the tour.

### 5. Tab links instead of escaping

With the cursor off a dotted word, `handleKeyDown` returned false and the
browser moved focus — onto the link-all corner button, which sits exactly
there. Tab now jumps to the next hint and promotes it, so repeated Tab walks
the chapter; it only surrenders focus when nothing is left to link.

### 6. A step's view is a function of the step

`the-consul` had **no route**. Forward it looked right only because creating
an element navigates to it as a side effect; backward there is no create, so
the pane kept a later step's element under the Consul's narration.

**Read this before touching `routeFor`**: `resolveRef` resolves against the
**BUNDLE**, not the store, so it succeeds for every scripted element whether
or not it has been revealed. My first fix routed on that alone and sent the
hands-on beat to a raw uuid reading "not found in this world" — worse than
the bug it replaced, **with all 18 tour e2e green**, because none of them
assert what the middle pane shows. The gate is existence ON DISK; the
fallback is world home.
