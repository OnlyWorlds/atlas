## The one to read first

**A renamed step id silently disarmed a gate, and nothing could see it.**

`tour-bar.ts` looked up `atlas-tour-preweb` by the step id `'where-it-lives'`.
S306c merged that step into `yours-to-keep`. `findIndex` returned **-1**, so
`idx < -1` was false for every step, the body class never applied, and the CSS
rule that hides the Web tab never matched. **The Web tab has been visible from
step 5 of 17 for the tour's entire post-S306 life** — while `linking`
deliberately withholds its name on the stated premise that it is hidden, and
`yours-to-keep` introduces it as arriving.

The general lesson: *a gate keyed on a string identifier fails OPEN when the
identifier is renamed, and a one-sided assertion cannot see it.* The suite
asserted the tab was PRESENT at step 16 and never that it was ABSENT before, so
a gate that stopped firing entirely stayed green. The fix is one word; the
durable part is the pair.

## What shipped

### Bout 0 — four defects a real user hits

1. **Nameless element broke the sidebar permanently.** `elements-sidebar.ts`
   sorted on a bare `a.name.localeCompare(b.name)` — the one sort site that
   skipped the guard every sibling uses. `name` is typed non-optional, which is
   exactly why it shipped: a type is a compile-time claim about data the
   compiler controls, and element JSON is data it does not. The Folder Format
   explicitly welcomes files from other tools.
   **Guarded by a source scan over all of src/, not a test of the one line**
   (`tests/unit/name-sort-guarded.test.ts`) — and it flagged two more sites on
   its first run. Both were false positives (`PaletteResult.name` is built as
   `el.name?.trim() || '(unnamed)'`); guarded anyway rather than allowlisted,
   because a text scan cannot tell an `Element` from a `PaletteResult` and an
   invariant with exceptions is one the next reader must re-derive.
2. **The preweb gate** above.
3. **Cmd+K could not find the Data room.** Branded "Data" everywhere except the
   two places that print it: a stale label-shortener in both `room-nav` render
   paths (written when the label was "Import & export") and a palette entry
   keyed on the route segment. Aliases added so "import"/"export" still match
   while "data" is what displays.
4. **`runPushOnly` had no try/catch where `runPullOnly` has one** — with a
   comment saying "we MUST restore idle state first or the pill stays stuck
   forever". Any throw left the pill reading "Saving…" indefinitely, on the path
   every user edit takes. Revert-checked (`expected 'syncing' to be 'idle'`).

### The palette — collapsed onto FOUR FAMILIES

Atlas shipped TWO unrelated 22-hue maps, visible simultaneously in the ordinary
three-pane view. Skeld's CVD validator refuted both, **and my own
recommendation with them**: I argued for `pin-visuals` because it was the only
palette with a stated rationale — an argument about structure. Theirs was about
perception: Title vs Trait are **ΔE 1.3** for deutan viewers, Character vs
Creature 6.3 against a floor of 15, Object and Construct below the chroma floor.

`core/element-colors.ts` is the single source, **deliberately shaped as the
SDK's proposed API** (`ELEMENT_FAMILIES` / `FAMILY_COLORS` / `elementColor`) so
the post-launch swap is a re-export, not a rewrite. Both old maps derive from it.

Two things the build produced that the validator could not:

- **Their hard case is different in atlas.** `map-tab-pins.ts:59` colours a pin
  by its TARGET element's type, so the Spatial hues essentially never render on
  a map. The fold into World is right for a different reason than modelled.
- **Luminance parity was never validated.** Against `#0a0a0a`: Temporal 6.84:1,
  Agents 5.77, Abstract 5.32, **World 4.25** — a 1.61x spread with the floor on
  the family covering Location/Object/Construct. Locations recede while events
  come forward; seen first, then measured. `#009a00` reads 5.62 and drops the
  spread to 1.29x. **Running as a PROPOSAL pending Skeld's re-validation** —
  raising luminance can shrink separation from a neighbour, which is the
  constraint their set exists to satisfy. One character to revert.

### Accessibility

**Icon ligatures WERE the accessible name.** Read off the live a11y tree,
controls announced as `"add cloud_upload"`, `"wall_art pages"`,
`"import_export import"`. 253 render sites, six `aria-hidden` in the whole
codebase, no shared icon helper to fix at — so `ui/icon-a11y.ts` creates the
boundary as one observer, **with its demolition date written in the file**
(post-launch: a real `icon()` helper, migrate, delete this).

**The sweep then created its own gap and its own audit caught it**: the type
filter buttons carry `data-tip`, not a label, so hiding the ligature made them
silent rather than wrong. `aria-label` added at the render site. Verified: 84
icons, zero unstamped, zero unnamed controls.

### Captain's round

- **Zone labels always-on for published pages.** The name was already in the
  payload and only reachable through a hover `<title>`.
- **The share-page zone click artifact, traced.** `role=button` + `tabindex=0`
  on an SVG path (correct, for keyboard) + no focus style anywhere = Chromium
  draws its UA focus ring, which on a stroked path renders as the black-and-white
  blob. `:focus-visible` keeps the keyboard ring and gives mouse clicks nothing.
  **`outline: none` alone would have fixed the picture and deleted the
  affordance the tabindex exists for.**
- **"element card" → "element", LABEL ONLY.** `kind: 'element-card'` is a
  persisted wire id, and `compilePageStory` is a derived artifact pushed to the
  server — renaming it would rewrite every existing page's story. Three tests
  caught the attempt.
- **Exit removed from the opener** — see the trap below.

### Tour TRUTH fixes (taste left alone; Captain is doing the copy pass)

Verified against the SDK and the bundle, not assumed:

- **`ELEMENT_SECTIONS.character` has a `World` section holding `objects` and
  `institutions`.** There is no "Possessions" and no "Affiliations" anywhere in

  things that step pointed at were named wrong.**
- **"all linked to the swamps zone" was false** for two of the four elements
  that step reveals, and schema-impossible for one (a collective has no zone
  field, so the copy implied a link the model cannot express).
- **`unlocks: ['rightpane']` moved from `the-planet` to `the-map`.** The biggest

  pane ABSENT at 5 and PRESENT at 6, so the timing is locked both ways.

### "More information" anchored (Captain, second round)

The deeper bulb lived in the copy flow right after the body, so its Y moved with
every step's copy length. On a fixed dock with a constant-height sentence above
and fixed rows below, the fix is to make the DOCKED copy fill the panel as a
column and push its footer to the bottom. Measured across steps 2/3/4/6 (body
1-3 lines, ghost placeholder and real bulb): the extras row now lands at
**89-91px from the dock bottom** on every step (was moving ~17px per body line).
CSS-only, scoped to `:not(.is-opener)`, every flex child reset because
flex-basis means HEIGHT once the direction turns column. Own-eyes confirmed.

## Where I was wrong, and how it was caught

- **My palette recommendation was refuted by measurement.** Structure is not
  perception.
- **My a11y suspicion was refuted by the run.** 11 landing buttons looked
  focusable from `offsetParent: null`; a real focusability walk found 3. They sit
  inside a `display:none` ancestor.
- **My "unused right column" in the dock was refuted by measurement** — content
  reaches 1141px of 1163px; the void is body copy on a correct reading measure.
- **The 429 gap in my own brief does not exist** (`make-online.ts:129` has an
  explicit branch). I had carried it forward from S307 on trust. A banked line is
  a claim, and that one had rotted. Eight banked items were already done.
- **Two instrument errors, both caught by the failure**: the push test injected
  at `folder.listElements`, which `pushPhase` never calls — the round SUCCEEDED.
  Real site is `listLocallyChangedSince`. And the preweb e2e asserted
  `toHaveCount(0)` against a CSS `display:none` gate, failing against the
  WORKING fix.
- **A single-class CSS rule lost a specificity tie-break** to
  `.atlas-welcome .material-symbols-outlined` (0,2,0) and rendered an inline
  glyph at 48px. My own craft law, bitten: check the existing selector first.

## The trap I refused to ship

Captain asked for the opener to carry one control. Doing exactly that leaves **no
way off the cover screen** for anyone who clicked "take the tour" to see what it
was. Escape now opens the exit confirm **on the opener only** — deliberately not
global, because S307 found a globally-captured Escape in zone edit with no target
check that reverted every committed vertex drag. The R3 relaunch spec now proves
the ESCAPE ROUTE survives unmount/remount, which is a stronger assertion than the
button check it replaced.
